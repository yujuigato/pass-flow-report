PASS 單的認定

PASS 日期為有效 8 碼日期，範圍 2010-01-01 到執行當天。原始約 21.3 萬筆中，約 3.7 萬筆是 PASS 單，其餘只有 Call 的紀錄不納入。

每張單的「時間窗」

-- 後續動作（日報／商機／成交）只看這個區間，避免把下一張單的事算進來
時間窗截止 = MIN( 同客戶下一張 PASS 單的日期,  PASS 日期 + 180 天 )
條件       = 日期 >= PASS 日期  AND  日期 < 時間窗截止

-- SDR 與行銷部門建立的紀錄不算「PASS 後業務接觸」
後續動作取法
業務日報（事業＋數科）窗內最早與最新各一筆，並計窗內筆數
商機（事業＋數科）窗內最早一筆（狀態 1／2／3）
成交訂單窗內最早一張，金額為該單明細加總
機會看板以 PASS 單號對應，取最新一筆（0 拒絕、1 待處理、2 完成、3 自動結案）

清理規則

項目做法
空白與換行換行、tab、全形空白統一為單一空白
填充值清掉沒有資訊的內容（NA、如描述、未定等）；「無」「暫無」只在「競爭」欄保留，其餘欄視為空
問候與結尾去掉「Dear 某某」問候語與結尾的謝謝
轉介套語「懇請／煩請指派規劃師聯繫」是電銷交接的固定收尾；12,786 單含此套語，拿掉後沒有實質內容的 69 單改標「待規劃師聯繫」
懸空引言內文以「如下：」等收尾而後面沒有內容的 2,007 單，去除該引言
補充說明拆欄固定範本「規模／現況／需求／使用人數／時程／預算／競爭／決策者／下一步預計行動／預計Demo方案／業務回饋」依關鍵字拆成欄位，範本外自由文字放「補充備註」
兩處都有填需求、現況、使用人數、時程、競爭在主表與補充說明都有值時，用「；」合併，相同或包含者不重複
短期再次 PASS同客戶 30 天內才視為連續；更久之後的單各自獨立
備註：2025 年之後的單，補充說明幾乎是空的（新系統不再使用該欄），固定架構欄位以主表欄位為主。

PASS 類型分類（規則，不呼叫 LLM）

兩段判斷，由上到下，先符合者為準。規則由實際內文寫法歸納而來。

第一段：內文開頭有「此為 XX」（約 29%，1,700 多種寫法）

依 XX 歸成固定類別，例如待確認商機、Callin／Callout PASS 單、補開立 PASS 單、二次 PASS 商機、單位轉 PASS 商機、客服／EGO 轉 PASS 商機、專案／活動支援、行銷高機會名單、歷史 PASS 客戶，其餘為「其他」。

第二段：沒有「此為」（約 71%）

看內文前 60 字的線索來源或用語；只述「有系統評估需求」而沒說來源者為「僅述系統需求」，都不符合者為「未標示」。

LLM：AI 業務摘要與 L1–L7 深度標籤

每張 PASS 單先組出「完整內容摘要」（結構化欄位＋業務原始描述；PASS 內容常常很短甚至空白，真正的內容其實填在需求、困擾等欄），再各呼叫一次 LLM，產出「AI 業務摘要」與 L1–L7 標籤。欄位 schema 與日報 Phase 2 完全對齊，之後可直接併入痛點需求機制整合。

層次萃取欄位
L1 起因／阻礙阻礙類型、影響範疇、急迫度（高／中／低）
L2 角色壓力角色、壓力來源、指標
L3 戰略目標目標類型、時間範圍、核心指標
L4 產業議題議題名稱、外部驅動力、態度（積極／觀望／防禦）
L5 問項精煉評估項目、比較對象（不含自家產品）、決策條件
L6 動態屬性走向（升溫／降溫／持平）、觸發事件、溫度（熱／暖／冷）
L7 實戰對策結果（簽約／報價／拒絕／延後／進行中）、關鍵因素、後續跟進；進行中時另有 L7_stage

工程設計

項目做法
快取以「完整內容摘要」的雜湊為 key，內容沒變不重打。最近一次重跑：候選 37,031 種不重複內容，快取已有 37,027 種，只需呼叫 4 種，約 13 秒
平行化執行緒池（20 workers）＋每分鐘請求上限，與日報系統同一套限流架構
失敗處理呼叫失敗的內容不寫入快取，下次重跑自動補
歸一化自由文字欄位做歸一化，沒有證據或內容過短（<10 字）則為空字串
L7_stageL7 結果為「進行中」者再細分：轉交業務、結案、提案／方案、說明／Demo、約訪／拜訪、評估／確認需求、提供資料、跟進、規劃中、其他
注意：L4_stance 近 99% 為「積極」，區分度低，不適合單獨篩選。L 標籤為 LLM 萃取結果，僅供參考，引用前請對照 PASS 日期與 AI 業務摘要判斷時效與正確性。

法人五階段彙整（S1–S5）

下一步與接手人

下一步取時間窗內最早發生的動作（二次 PASS、轉入業務私田、商機、成交、短期再次 PASS），其他動作並列在「後續動作」。接手人為首次業務日報的建立人，與 PASS_SP、PASS 窗口及內文載明的 SP 比對，得出「接手人是否為 PASS 指定」（為「否」不一定有誤，可能轉給同事或先由電銷聯繫）。

輸出的四張表

表一列代表寫入方式
pass_detail一張 PASS 單（含該單的 L1–L7）每次整張重建
pass_company_summary一家公司（目前最新狀態）每次整張重建

兩個維度怎麼分工

單的維度：pass_detail
只放「當次」PASS 單本身，不帶後續。包含識別與日期、分類（負責類型、PASS 類型、PASS 來源、五大類、等級、工作狀態）、客戶資訊固定架構（規模、需求、使用人數、現況、困擾、時程、預算、競爭、決策者、據點、主要產品、下一步、Demo 方案、業務回饋）、指派與建立資訊、PASS 內容與 AI 業務摘要、L1–L7。要查某公司所有過往 PASS 單與標籤，只查這一張即可。
法人的維度：pass_company_summary
一家公司一列，S1–S5 五段彙整；每張單的後續（S2–S5）仍以該單的時間窗判斷，再彙總到法人，單層級後續不寫入資料庫。

歷史快照規則

比對時不看「快照日期」「寫入時間」；公司第一次出現，或內容與歷史表最新一筆不同，才附加一列。同一天重跑、沒有變動不會重複附加。欄位改版時保留舊列重建。

查詢範例

-- 某家公司所有過往 PASS 單（新到舊），含深度標籤
SELECT PASS日期, 等級, 狀態分類, 需求, 困擾, AI業務摘要,
       L6_current_temp, L6_direction, L7_outcome_type, L7_stage, L5_competitors, L7_next_step
FROM pass_detail
WHERE 潛客代號 = N'請填潛客代號'
ORDER BY PASS日期 DESC;

-- 月度統計（取代全歷史月度表）
SELECT 潛客代號, 年月, COUNT(*) AS 當月PASS單數
FROM pass_detail
GROUP BY 潛客代號, 年月;

已知限制

  • 資料範圍是全公司，不只單一產業。
  • 只有 Call 紀錄、沒有 PASS 日期的資料不納入。
  • 當天剛建立的單，後續欄位為空屬正常。
  • 業務私田的接手時間只能參考日報；歸屬表只有現任歸屬，沒有歷史。
  • 9 大問題的確切欄位尚未確認，目前沒有計算完整度。
  • 重複執行 --write：前三張重建，歷史表再附加一份快照（有變才附加）。
